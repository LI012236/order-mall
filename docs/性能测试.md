# 性能测试报告

## 一、环境

| 项 | 配置 |
|---|---|
| 机器 | 本机（Windows），单机部署 |
| 服务 | Spring Boot 3.2.5 内嵌 Tomcat，JVM 默认参数 |
| 数据库 | MySQL 8.3，本机，HikariCP 最大连接 20 |
| 客户端 | Python 线程脚本 `scripts/load_test.py`，与服务同机 |
| 网络 | 回环（无网络损耗） |

> 说明：压测端与服务端同机，会互相抢 CPU，绝对值仅供横向对比，不代表生产容量。

## 二、场景与结果

### 场景 1：商品列表（只读）

```bash
python scripts/load_test.py --api products --concurrency 20 --total 500
```

| 指标 | 数值 |
|---|---|
| 并发 | 20 |
| 总请求 | 500 |
| 总耗时 | 1.49 s |
| **TPS** | **335.7** |
| 成功率 | 100% |
| 平均耗时 | 56.9 ms |
| P95 | 84.6 ms |
| P99 | 102.1 ms |

### 场景 2：加入购物车（单表写入）

```bash
python scripts/load_test.py --api cart --concurrency 20 --total 300
```

| 指标 | 数值 |
|---|---|
| 并发 | 20 |
| 总请求 | 300 |
| 总耗时 | 2.59 s |
| **TPS** | **115.9** |
| 成功率 | 100% |
| 平均耗时 | 164.7 ms |
| P95 | 239.8 ms |
| P99 | 277.7 ms |

### 场景 3：完整下单链路（加购 + 下单，含事务）

```bash
python scripts/load_test.py --api checkout --concurrency 10 --total 100
```

| 指标 | 数值 |
|---|---|
| 并发 | 10（每线程独立账号） |
| 总请求 | 100（每次 2 个接口调用） |
| 总耗时 | 1.39 s |
| **TPS** | **72.0**（业务单量） |
| 成功率 | 100% |
| 平均耗时 | 132.3 ms |
| P95 | 157.8 ms |
| P99 | 166.6 ms |
| **数据一致性** | 订单数 65 → 165（+100），库存 999318 → 999218（-100） |

**结论**：100 次下单产生的订单数与库存扣减量完全一致，**没有超卖、没有少卖**。

## 三、分析

1. **只读 QPS 是写入的 3 倍**（335 vs 116）。瓶颈不在 Tomcat 线程，而在 MySQL 单行更新。
2. **购物车场景 P95 明显偏高**（240ms）。原因是 20 个线程操作**同一个用户**的购物车，`uk_user_product` 这一行被反复加锁，形成热点行竞争。换成每用户独立线程后，延迟会显著下降——这正好印证「热点行更新是并发瓶颈」。
3. **下单 TPS 72**，每次下单包含：开事务、条件更新库存、插入订单、批量插入明细、删除购物车、提交。5 次数据库往返，属于合理区间。
4. **P99 是 P95 的 1.2 倍左右**，说明没有长时间卡顿（无 GC 长暂停、无锁等待雪崩）。

## 四、可优化方向（面试可讲）

| 方向 | 做法 | 预期收益 |
|---|---|---|
| 连接池 | 当前 Hikari 最大 20，压测并发 20 时容易排队；调到 50 并观察 DB 连接数 | 降低 P95 |
| 库存热点 | 同 SKU 高并发时条件更新会串行化；可拆分库存（分桶）或 Redis 预扣 + 异步落库 | 提升下单 TPS |
| 读写分离 | 商品列表走从库 | 读吞吐翻倍 |
| 缓存 | 商品详情加 Redis，热点商品命中率 90%+ | 读延迟降到个位数 ms |
| 批量 | 订单明细已用 `batchUpdate`，可再合并库存更新 | 减少往返 |
| JVM | 指定堆大小与 GC（如 G1 + `-Xmx2g`） | 降低 GC 抖动 |

## 五、如何复现

```powershell
# 1. 起服务
java '-Dfile.encoding=UTF-8' -jar backend\target\order-mall.jar

# 2. 跑三个场景
python scripts\load_test.py --api products --concurrency 20 --total 500
python scripts\load_test.py --api cart     --concurrency 20 --total 300
python scripts\load_test.py --api checkout --concurrency 10 --total 100
```

> 下单场景会自动把商品 1 的库存调到 200 万，避免压测中途售罄。
